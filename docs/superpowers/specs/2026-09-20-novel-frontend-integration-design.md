# 小说前端接入现有系统设计方案

## 目标

在现有 LinkScope 仓库中新增一个独立的 Vue 3 奇幻文学前端，同时保持现有管理后台、产品落地页、短链接路由、PostgreSQL 数据库、广告归因规则和部署方式不变。

小说站提供沉浸式首页、文章列表和长文详情页。第一版所有短链接 code 共用同一套文学内容。code 只负责解析现有 `short_links` 记录、归属访问数据、确定 WhatsApp 目标地址，以及读取对应的 Meta 配置。

## 功能范围

### 包含内容

- 新增独立的 `novel/` Vue 3 + JavaScript + Vite + Vue Router 应用。
- 提供小说首页、文章列表、文章详情、页面访问确认和手动 WhatsApp 咨询路由。
- 复用现有短链接记录、访客分类、广告归因参数、签名访问票据、Meta PageView、手动咨询事件和 WhatsApp 目标地址。
- 增加入口类型维度，用于区分现有短链接流量与小说站流量。
- 调整管理后台数据总览、访问明细、筛选和 CSV 导出，使两类入口可以分别查看。
- 调整 Docker 和发布流程，使同一个 Gin 服务能够构建并托管第三个前端。

### 暂不包含

- 小说内容管理后台或增删改接口。
- 每个 code 使用不同的小说内容或视觉主题。
- 小说页面倒计时自动跳转 WhatsApp。
- 替换或重命名现有 `/:code` 短链接路由。
- 复制参考站的 Logo、插画或小说正文。

## 路由与应用边界

仓库内保留三个相互独立构建的前端应用：

- `frontend/`：位于 `/admin/*` 的现有登录管理后台。
- `landing/`：现有 `/:code` 在落地页模式下使用的产品落地前端。
- `novel/`：新增的 `/novel/:code/*` 公共文学前端。

小说站公开路由如下：

- `GET|HEAD /novel/:code`：小说站首页。
- `GET|HEAD /novel/:code/stories`：文章列表。
- `GET|HEAD /novel/:code/stories/:slug`：文章详情。
- `POST /novel/:code/view`：确认 PageView 上报。
- `POST /novel/:code/contact`：手动 WhatsApp 咨询。
- `GET|HEAD /novel-assets/*filepath`：带内容版本号的小说前端资源。

现有 `/:code`、`/:code/view` 和 `/:code/contact` 路由保持原行为。Gin 必须在通用 `/:code` 路由之前注册所有 `/novel/*` 路由，防止通用短码路由抢占请求。

Vue Router 从当前地址读取 code，并在所有站内链接中保留该 code。在已经挂载的单页应用内切换首页、列表和详情时，不重复记录入口访问；直接打开或刷新任意小说路由时，记录一次新的入口访问并签发新的访问票据。

## 小说内容与视觉系统

第一版在 `novel` 应用中保存一套构建期共享内容。每篇文章使用结构化 JavaScript 对象，包含 slug、标题、作者、发布日期、分类、摘要、可选图片、作者简介和正文块。正文块只允许文本段落与明确的章节分隔标记，不渲染任意 HTML。

视觉体验参考目标站的结构，但不复制其品牌和素材：

- 首页使用全视口奇幻插画，只突出最新文章入口。
- 列表和详情使用固定插画背景，上层覆盖带阴影的白色阅读纸张。
- 使用独立英文品牌、衬线字体、浅金色展示标题和响应式导航。
- 文章列表每页显示 6 篇。
- 详情页支持字号减小、增大、重置和页面内沉浸阅读。
- 阅读字号保存在浏览器本地。
- 按相同分类确定性选择最多 3 篇相关文章，并排除当前文章。
- 页面保留手动 WhatsApp 按钮，但不得打断正常阅读。

图片缺失时使用符合主题的渐变背景，不显示破图。应用需要提供加载、code 不可用、链接已停用和服务异常状态。背景、Logo 和文章图片必须使用原创、已授权或为本项目专门生成的素材。

## 后端接入

### 复用短链接配置

小说入口处理器通过 `short_links.code` 查询现有记录，并要求链接处于启用状态。小说入口不依赖链接当前的 `mode`：同一条启用记录可以继续让 `/:code` 按原配置执行直接跳转或产品落地页，同时让 `/novel/:code` 展示文学站。

现有追踪处理器中的请求分类和归因逻辑必须复用，不能复制一套相似实现。小说入口创建普通落地页类型的访问记录，并保留原 `link_id`、WhatsApp 目标地址、广告系列参数、访客状态、Meta 连接和 Pixel 快照。

### 入口类型字段

新增数据库迁移，在 `click_events` 中加入非空 `surface` 字段：

- `short_link`：历史数据和所有现有 `/:code` 流量的默认值。
- `novel`：所有 `/novel/:code/*` 入口流量。

现有 `event_type=landing|redirect` 语义保持不变。这能够保留现有漏斗查询和咨询行为，同时明确访问从哪种页面进入。后续所有新访问记录都必须显式写入 surface。

数据总览和单链接统计需要分别返回短链接访问、小说站访问、短链接咨询和小说站咨询。访问明细支持 `short_link`、`novel` 筛选，并显示入口类型；CSV 导出追加 `surface` 字段。为避免破坏现有调用方，原有汇总字段继续保留，新增字段作为补充。

### 签名与咨询操作

小说站票据的签名内容必须同时绑定事件 ID、code 和 `novel` 入口类型。小说咨询接口只接受手动操作，拒绝自动跳转触发。数据库更新只允许处理一小时内、属于当前链接、`event_type='landing'` 且 `surface='novel'` 的 GET 访问记录。

现有短链接票据与咨询接口继续要求 `surface='short_link'`。两种票据不能跨入口重放。小说站同一次访问的手动咨询保持幂等，成功后返回原短链接记录中的 WhatsApp 目标地址。

Meta 浏览器 PageView 与服务端事件继续使用现有事件 ID 去重机制。小说站使用独立的启动数据标记和内容安全策略，但只允许当前系统已需要的自身域名、Meta 和 WhatsApp 来源。

## 页面输出与静态资源

小说页面输出器读取 `NOVEL_DIR/index.html`，将唯一的小说启动数据标记替换为服务端 JSON，并更新页面标题、描述和分享元数据后返回对应 HTTP 状态。

启动数据仅包含公开短链接字段、签名票据、Cookie/统计开关、公开 Pixel ID、事件 ID 和可选错误信息。不得向浏览器暴露密钥、内部 Meta 凭证或不必要的数据库字段。

配置新增 `NovelDir`，从 `NOVEL_DIR` 读取，本地默认路径为 `../novel/dist`。运行镜像将 `novel/dist` 复制到 `/app/novel`，并设置 `NOVEL_DIR=/app/novel`。小说资源统一使用 `/novel-assets/`，避免与管理后台和现有落地页资源冲突。

## 错误与兼容行为

- code 不存在：返回带小说站样式的 404 页面和 HTTP 404。
- code 已停用：返回带小说站样式的 410 页面和 HTTP 410。
- 数据库查询失败：返回 HTTP 503，不伪造访问记录。
- 查询成功但访问写入失败：仍展示小说站，但不提供签名票据；WhatsApp 按钮降级为直接目标链接，并明确存在统计缺口。
- 咨询写入失败：返回可重试的 HTTP 503。
- 票据无效、过期或跨入口使用：返回 HTTP 400。
- 现有短链接、管理后台、API、静态缓存、请求日志和产品落地页保持兼容。

访客请求日志纳入小说 HTML 入口、view 和 contact 请求，但继续排除带版本号的静态资源。请求头和正文沿用现有脱敏与大小限制。

## 测试与验收

后端测试覆盖：

- `/novel/*` 与 `/:code` 的路由优先级。
- 正常、缺失、停用、HEAD 和数据库故障下的小说入口。
- 短链接与小说访问分别写入正确 surface。
- 小说手动咨询成功、幂等、过期、错误签名和跨入口重放拒绝。
- 小说入口拒绝自动咨询。
- Meta PageView 与手动事件的去重 ID。
- 数据总览、单链接统计、筛选、访问明细和 CSV 的入口类型结果。
- 启动数据安全转义、内容安全策略、页面元数据和静态缓存。

前端测试覆盖：

- 首页、列表、详情、相关推荐和返回链接始终保留当前 code。
- 每页 6 篇文章的分页、空状态和文章不存在状态。
- 阅读字号上下限与刷新后恢复。
- 沉浸模式进入、退出和 Escape 操作。
- 有签名票据和降级状态下的 WhatsApp 咨询。
- 360px、768px、1440px 三档视口不存在横向滚动、遮挡或正文溢出。

发布验收必须通过三个前端的测试和构建，以及 `go test ./...` 和 `go vet ./...`。生产容器必须由同一个 Gin 进程正确提供管理后台、现有产品落地页、小说页面及三个互不冲突的资源路径。除新增 surface 的明确断言外，现有短链接集成测试必须继续通过。

## 实施约束

- 保留仓库内全部已有未提交改动，不执行无关重构。
- 不创建或推送 GitHub 提交。
- 实现保持直接、简洁，并遵循现有模块边界。
- 在路由优先级、入口类型签名、统计复用等不直观逻辑处添加简洁中文注释。
- 不为简单页面逻辑进行过度封装。
